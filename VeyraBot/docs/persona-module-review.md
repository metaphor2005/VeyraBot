# 人格 / 性格模块评审与优化建议

> 对象：`cognitive/persona/{kernel,snapshot,changelog}.py`、`config.PERSONA_*`、`prompts.render_persona_profile`、`cognitive/cognition/archiver.py`、`cognitive/storage/{database,kg_store}.py`
> 状态：**2.1 / 2.2 / 2.3 / 2.4 / 3.2 已落地并通过探针（见 §9 变更记录）；3.1 / 3.3 / 3.4 / §5 待做（依赖信念层的 `belief_id` / 人际曲线，尚在 spec 阶段）。**

---

## 0. 结论

骨架是对的，不建议重做：**基调（base）+ 日内摆动（value，±0.15）+ 日结推进（±0.01/天）+ 累计 0.06 才出新版本**，这套节奏确实能把"一天一个样"按住。

问题不在骨架，在四条线没接上：

| 线 | 现状 | 缺什么 |
|---|---|---|
| **时间** | 情绪只在"有对话的那几轮"里衰减 | 隔三天回来，情绪强度原封不动 |
| **强度** | 被摆动带夹住之后，当天继续施压不再累计 | "被反复顶住"和"被顶一次"日结结果一样 |
| **因果** | 变迁日志只记参数和自我认知 | 信念被推翻时，人格层一个字都没有 |
| **表达** | 参数→倾向→prompt 是通的 | 好感算出来了，但不影响说话方式 |

另外有一处**文档承诺与实现不一致**：README 写"人格 = 浮点参数 + **KG 信念权重** + 情景状态"，但代码里 `core_beliefs` 只是拿出来塞进 Prompt，**从不参与参数演化**。

## 1. 现在的样子（读取代码得到的事实；⭐ 为评审时的状态，改动见 §9）

| 模块 | 存什么 | 每轮怎么用 |
|---|---|---|
| `kernel.py` | `persona_kernel`：14 个参数 × (`base_value` / `value` / `pending_value`) | `get_params()` 取当前值、`describe()` 翻成行为倾向 |
| `kernel.py` | `persona_mood`：5 类情景 (`mode`,`intensity`,`decay_rate`) | ⭐ 每轮末尾 ×0.82，低于 0.15 直接删行（改后：按小时 + 按轮双段） |
| `snapshot.py` | `data/persona_snapshots/{space}/v{N}_{topic}.json`，只加载当前版本 | 每轮读 `self_view` / `narrative` |
| `changelog.py` | `persona_changelog`，append-only | 只在"你为什么变"类问题里被 `render_history()` 读 |
| `config` | `PERSONA_PROFILE` 7 组 40 余条 + `KERNEL_INIT` 14 项 | **每轮全量渲染进 Prompt** |

每轮链路：`describe()` + `live_self_view` + `query_core_beliefs(importance≥0.75, 前12条)` → 组装 Prompt。
日结链路：`pending × 0.35`，夹到 `±0.01`，移动 `base`，`value` 复位到新 `base`，累计 ≥0.06 才 `create()` 新快照。

## 2. P0：会真出错的四条

### 2.1 情绪只按"轮"衰减，不按时间

**现状**：`decay_moods()` 只在每轮归档末尾调用；`persona_mood` 表里只有 `create_ts`，没有"上次衰减时间"。

**后果**：周五聊到 `empathetic=0.85`，周一来打招呼，读到还是 `0.85`——她会用三天前那股情绪接一句"你好"。真人不会这样。

**改法（已实现）**

- `persona_mood` 增列 `last_decay_ts`（走 `_COLUMN_MIGRATIONS`，老库自动补齐，新库同样生效）
- 读/写前先按经过时间衰减：`intensity ← intensity × exp(−λ_h × Δh)`，`λ_h = MOOD_DECAY_LAMBDA_HOUR = 0.02`（半衰期约 35 小时）
- 轮次内**保留** `×0.82` 的快速衰减（对话中的情绪回落本来就快），两段叠加
- `Δh < MOOD_TIME_DECAY_MIN_HOURS (0.5h)` 时跳过，避免每轮重复折算
- `set_mood` 也先把旧强度衰减到此刻再取 max，否则昨夜的余温会被当成"此刻的状态"参与比较
- **`get_moods()` 读的时候也要折算**（只读不写，落库仍交给 `decay_moods`）。这是复检时补上的关键一条：本轮读 Prompt 发生在任何 `decay_moods()` 之前，不在这里折算，"隔三天用三天前的情绪接第一句话"依然存在。低于阈值的条目读时直接不返回

**探针**（已跑）：`0.80` 回拨 72h → `get_moods()` 直接读到 `0.190`（`describe()` 不再提共情）；`decay_moods` 落库为 `0.155`；回拨 200h → **行被删除**；回拨 10h → `0.737`（`0.90×e^-0.2`）。

### 2.2 顶到摆动带之后，当天的"力度"不再累计

**现状**（`kernel.apply_deltas`）：先夹制 `new_value` 到 `base ± 0.15`，再 `pending += (new_value − old_value)`；一旦到边界，差值为 0，走进 `continue` 分支，**pending 完全不增长**。

**后果**：`base=0.50`、band 上限 `0.65`，连写 4 次同向 `+0.05`——现值停在 `0.65` 是对的，但 `pending` 只有 `0.15`（正确的"当天总压力"应是 `0.20`）。也就是说：**今天被人反复按着同一个点顶了十次，和顶了一次，日结移动一样多。** 这与"人格靠日积月累"的设计意图直接冲突。

**改法（已实现）**

- `pending` 记 **原始 delta 之和**（未夹制），`value` 仍按 band 夹
- 新增 `PERSONA_PENDING_CAP = 3.0` 兜物理上限（一天被同向顶几十次也不无限累加）
- 日结的 `±0.01` 上限天然兜底，不会被"一天骂十句"推飞
- 数值没动（已顶到边界）时仍要写 `pending`，再 `continue`

**探针**（已跑）：`base=0.5`、band `±0.15`，连写 4 次 `+0.05` → 现值 `0.65`、`pending = 0.20`（改前 `0.15`）。

### 2.3 信念被推翻，人格层零记录

**现状**：`models.PersonaChange` 的注释里明明写着维度是 `kernel:{param} / self_view / mood:{mode} / belief:{name}`，但全库 grep 下来，**只有 `kernel:` 和 `self_view` 两种真正被写入过**。`archiver` 的信念冲突只往 `experience` 里塞了一行 `【信念更替】…`。

**后果**：用户问"你为什么这么想"，`render_history()` 只能答参数漂移，答不出"因为那件事我改了想法"。这正是这套系统最该有的回答，反而是空的。

**改法（已按此实现）**

- 信念被**否决/覆盖**且够"核心"时，追加一条：
  - `persona_field = belief:{head}·{rel}`（按槽位命名，可读、可按槽位过滤；`belief_id` 落地后可平滑换成 13 位编号）
  - `old_value = 原句`，`new_value = 新句`
  - `reason = 当轮 topic 摘要`
  - `source_type = dialogue`
- **两档门槛**（不能只按"涉及自我"放行，否则"我更喜欢橘子了"天天进日志）：
  - `importance ≥ PERSONA_BELIEF_LOG_IMPORTANCE (0.90)` → 记，不管涉及谁
  - 涉及她自己 且 `importance ≥ PERSONA_BELIEF_LOG_SELF_IMPORTANCE (0.60)` → 记
- 放在 `archiver` 的冲突分支里写，不要等日结（因果一旦丢就补不回来）

**探针**（已跑，见 §9）：
- 她自己 + 0.95 被覆盖 → 记 1 条
- 她自己 + 0.30（琐碎偏好）被覆盖 → **不记**
- 不涉及她但 0.95 被覆盖 → 记 1 条

### 2.4 快照里的核心信念不随时间

**现状**：`kg.query_core_beliefs` 只按 `importance desc` 取前 12 条，不看 `confidence`、不看时间、不过滤 `dormant`。

**后果**：三个月前某条 `importance=0.9` 的信念永远占着快照的前排，新近的、真正高置信的信念挤不进去。快照反映的是"曾经的她"，不是"现在的她"。

**改法（已实现）**：排序改 `order by (confidence * importance) desc, confidence desc`，`is_active = 1`。

**探针**（已跑）：造"90 天前、importance 0.95、confidence 0.20"+"今天、importance 0.80、confidence 0.90" → 新近那条 `0.720` 排第一，老的 `0.190` 掉到第二。

## 3. P1：会让"她"失真的四条

### 3.1 信念不驱动参数（README 承诺了，代码没做）

**现状**：`core_beliefs` 只进 Prompt 文本，`settle_daily` 只看 `pending`（来自抽取器的 `persona_deltas`）。

**为什么不能简单接上**：如果每条信念都去推参数，她会变成"被对话拟合出来的函数"，这正是你要避免的。

**改法（限定三条映射，宁可少）**

| 信念情形 | 影响参数 | 单次幅度 |
|---|---|---|
| 新增/否决**涉及自身能力或价值**的核心信念 | `self_reflect_threshold` ↓ / `novelty_bias` ↑ | 0.004 |
| 被抓到**前后不一致**并承认 | `consistency_priority` ↑ | 0.005 |
| 人际信任类信念被否（被背叛） | `harmony_priority` ↓ | 0.003 |

- 只在"新增 / 否决核心信念"时触发，**不按轮触发**
- 单参数单日累计上限 `0.005`（小于 `PERSONA_DAILY_MAX_STEP=0.01`，确保信念单独**永远不足以**造成一次版本跃迁）
- 每次触发都要写 `changelog`，理由写"因为哪条信念"

### 3.2 `describe()` 是阶跃函数，而且只看高值

**现状**：阈值 `0.6 / 0.75 / 0.8` 硬编码；只有"高"才描述，"低"没有任何输出。

**后果**：参数从 0.59 飘到 0.61，行为描述突然跳一句；而 `prefer_decompose=0.2`（极不爱拆解）这种**同样有辨识度**的特征，完全不被表达。

**改法（已实现）**

- 三级阈值进 config：`PERSONA_DESC_STRONG 0.72` / `PERSONA_DESC_MID 0.45` / `PERSONA_DESC_WEAK 0.28`
- 每个参数配**三套文本**（高 / 中 / 低）。低值不是"没有倾向"，是**反向倾向**（"你先说结论再补细节"）
- `(0.28, 0.45)` 之间视为接近中性，不描述，避免堆废话
- 按 `|value − 0.5|` 倒序输出（先讲此刻最鲜明的特征），封顶 `PERSONA_DESC_MAX_LINES = 8` 行
- 注意 `self_reflect_threshold` 是**反向语义**参数（值越低越容易反思），三套文本按方向写好，别跟着其它参数一起读反

**为什么必须补中档**：只做"高/低"两档时，默认参数（0.38~0.78）几乎全落在中间，实测只出 3 行——人格倾向区块等于没注入。补中档后默认状态 8 行（封顶生效）。

### 3.3 好感不进表达

**现状**：`interpersonal` 那条曲线（见 `belief-system-spec.md` §5.5）算出了好感，但 `describe()` 里一个字都没用。结果是：**她对谁都一样热情**，好感这个变量白算。

**改法**：`describe()` 尾部加一档"关系温度"，只给倾向、不给数值：

| 好感 | 表达倾向 |
|---|---|
| `≥0.70` | 放松，可以主动提旧事、开玩笑、用省略号 |
| `0.40~0.70` | 常态礼貌 |
| `<0.40` | 客气、少主动、不追问私事、不主动提往事 |

注意：数值绝不进 Prompt，只进"倾向"；否则她会把"我对你 0.62"说出来。

### 3.4 档案全量注入，而且"当下"会过期

**现状**：`render_persona_profile()` 把 7 组 40 余条**每轮全量**塞进 Prompt（估算 900~1200 token/轮）。其中【当下（2026-11）】写的是"准备 12 月漫展的陈·常服""愁高数期中"——**这是会烂的内容**。年龄"18 岁"也是写死的，生日 2008-03-03，到 2027 年 3 月就不对了。

**改法**

- **分层注入**：常驻 = 身份 / 性格三层 / 偏好与雷区（约 15 条）；生活切片、关系网、能力短板按话题命中才注入（复用 `synonyms` 的关键词命中）
- **"当下"组不要写死**：由日结用近 7 天 topic 摘要自动生成一句话，写进 `persona_meta.live_now`；生成失败则留空，别回落到过期文本
- **年龄按生日算**，不写常量；生日可以从 `PROFILE` 里解析，或直接进 config 为 `PERSONA_BIRTHDAY`

**效果**：常驻区块 token 降约 40%，同时"最近怎么样"能答出这个月的事，而不是去年 11 月的事。

## 5. 与信念系统的接口（必须和信念改造同批做）

这三处不同批改，两套系统就会各说各话。

### 5.1 `importance` 必须由代码算，不能信模型自报

现在 `importance` 是抽取器让模型每轮填的（技术细节 0.3~0.5、用户偏好 0.5~0.7、自身定位 0.8~1.0）。而它在信念系统里**直接决定衰减速度**（`λ_eff = λ × (1 − 0.6×importance)`）和大事判定（≥0.9）。

模型自报的重要性天然偏高（它倾向于把什么都写得重要），后果是**所有信念都衰减得很慢**，等于没有遗忘。

**改法**：`importance = 0.6 × 类型基线 + 0.4 × 结构信号`

- 类型基线：自身定位 0.90 / 人际 0.75 / 用户偏好 0.60 / 技术细节 0.35
- 结构信号：涉及 `AgentSelf` +0.15、被提及 ≥3 次 +0.10、被用户纠正过 +0.10，封顶 1.0
- 模型给的 `importance` 降级为"提示"，只用来排序候选，不直接入库

### 5.2 信念 → 参数：只三条映射（见 3.1）

### 5.3 信念 → 情绪：被否就该难受

核心信念被推翻时，自动触发 `self_reflect`（0.5）+ `skeptical`（0.4）两个 mood。现在这个时刻她**什么情绪都没有**，只是默默改了个字段——这是最不像人的地方之一。

## 6. 不建议做的（避免过度设计）

1. **别让参数每轮被信念拉动**——会变成拟合器，人格失去稳定性
2. **别上完整情绪模型**（PAD / OCEAN / 大五人格）——14 个参数 + 5 类情景已经够表达，再加一层只会互相解释不清
3. **别让模型直接写参数**——现在抽取器的 `±0.15` + band + 日结三层夹制刚好，放开就失控
4. **别给"性格"再加一层文本**——档案是皮相、参数是骨相、快照是叙事，再加第四层必然打架

## 7. 落地顺序

```
第 1 步  2.1 情绪按时间衰减 + 2.2 pending 记原始力度     ← ✅ 已完成
第 2 步  2.3 信念变迁进 changelog + 2.4 核心信念排序       ← ✅ 已完成
第 3 步  3.2 describe 三档描述                            ← ✅ 已完成
          3.3 好感动表达                                  ← ⏳ 待信念层人际曲线落地
第 4 步  3.4 档案分层 + "当下"自动化 + 年龄按生日算        ← ⏳ 未做
第 5 步  5.1 importance 代码校准 → 3.1 三条映射 → 5.3 信念→情绪  ← ⏳ 未做
第 6 步  4.1 / 4.2 / 4.3                                  ← ⏳ 未做
```

第 1、2 步做完，她就"记得住、也忘得掉"；第 3、4 步做完，她才"对人有区别、说话不撞车"；第 5 步是最后做的，因为最容易过拟合。

**为什么 3.3 / 3.1 / 5.1 停在这里**：它们都要读 `belief_id`、`cardinality`、人际好感曲线——这些还只在 `belief-system-spec.md` 里，代码一行未动。先在人格层单方面接上去，接的是一张还不存在的表。

### 9.1 复检时新发现（比原方案深一层）

1. **`get_moods()` 读路径不折算**：原方案只在 `decay_moods()` 里按时间衰减，但每轮读 Prompt 发生在任何 decay 之前——用户隔三天回来，第一句话仍然读到三天前的 `0.80`。修法是在 `get_moods()` 里也做一次只读折算。**不修这条，2.1 等于没修。**
2. **`describe()` 行数封顶只管参数行**：情绪行是循环后追加的，最坏情况 8 + 5 = 13 行。改成给情绪行预留预算。
3. **同幅度参数排序不稳定**：`sorted` 的 key 只有幅值，同值时按字典插入顺序（来自无序 SQL），两次调用可能换序。补参数名做次序。
4. **`config.py` 注释被误改**：`PERSONA_DAILY_LEARNING_RATE` 上方多出一个"# 上限："前缀、丢了"约三分之一净偏移"的说明，已修回。
