# 记忆架构技术笔记

## 一、普通 RAG 的局限

普通 RAG 的链路是：文档切块 → 向量化入库 → 查询时相似度检索 → 把片段拼进提示词。它解决的是"模型缺少外部资料"的问题，但存在三个结构性缺陷：

1. 召回单元是文本块，不是事件。一段跨多轮的讨论会被切成多个碎片，检索时容易拿到断章取义的片段。
2. 没有状态。所有片段平等参与相似度计算，旧观点、已被推翻的结论、过期人格会和当前有效信念一起被召回。
3. 没有因果。它只能回答"哪段文字最像"，无法回答"我为什么改变了想法"。

## 二、Topic-Centric 主题索引记忆

Topic-Centric 把一次完整交互归纳为一个 topic，作为最小记忆单元：

- topic 主记录包含：标题、摘要、关键词、时间、绑定的会话与人格快照版本。
- 向量索引只索引 topic 摘要，不索引零散对话碎片。
- 检索流程是两层：先用向量召回相关 topic，再按 topic_id 取回该事件下挂载的全部经验片段与关联信念。
- 召回单位因此从"一段文字"变成"一件往事"，上下文自洽，不易断章取义。

与普通 RAG 的关键差异：普通 RAG 是碎片检索，Topic-Centric 是事件检索。

## 三、Graph RAG

Graph RAG 在向量检索之上叠加实体关系图：

- 先把文本中的实体与关系抽出来，构建知识图谱。
- 检索时同时使用语义相似度与图上的多跳遍历。
- 适合"顺着概念联想"：由 A 想到 B，再想到 C。

其代价是抽取成本高，且容易与已有的业务知识图谱产生两份不同步的知识。工程上更稳妥的做法是复用同一套图，只在其上增加图遍历查询能力，而不是重新抽一遍。

## 四、分层记忆的推荐组合

- 短期工作记忆：会话上下文，带 token 安全阈值与兜底摘要压缩。压缩是应急保护，不是记忆归档。
- 结构化信念：属性图存储，带置信度、重要性、生效标记。用于精确查询、冲突检测、版本溯源。
- 事件记忆：主题索引 + 向量检索，用于模糊回忆与经验复用。
- 人格层：符号化参数（可计算、可衰减、可阈值判定）与叙事快照（独立文件、按版本管理）分离。参数驱动行为，叙事只做自我描述。
- 兜底检索：RAG 不前置，由信息充足度判决决定是否启用。

## 五、结论

普通 RAG 适合做资料查询插件，不适合作为认知系统的主链路。复杂系统应按记忆类型选择存储与检索方式：精确约束走图查询，模糊经验走主题索引，外部资料走 RAG 兜底。
